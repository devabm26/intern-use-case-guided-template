# Compliance Mechanisms: How Security is Enforced

**Understanding when compliance is automatic vs. when it requires explicit prompting**

---

## 🎯 The Question

> "When prompting happens, does the user need to specify 'comply with specs' or does it happen automatically?"

**Answer:** It depends on the AI tool being used.

---

## 🔒 Three Layers of Enforcement

This template uses **defense in depth** with multiple enforcement layers:

### Layer 1: AI Guidance (Preventive - Varies by Tool)
### Layer 2: Testing (Detective - Always Required)
### Layer 3: CI/CD Gates (Blocking - Always Required)

---

## 🟢 Layer 1: AI Guidance (When is it Automatic?)

### Claude Code (Anthropic CLI) - SEMI-AUTOMATIC ✅

**What Happens Automatically:**
```
User opens project
  ↓
Claude Code detects .claude/project-instructions.md
  ↓
Automatically loads compliance requirements
  ↓
Claude knows to read specs before coding
  ↓
User: "Add database connection"
  ↓
Claude: "Reading specs/architecture/database_layer.spec..."
  ↓
Claude: [implements following spec]
```

**What User Still Needs:**
- Describe the task clearly
- Provide business requirements
- Approve implementation approach

**User Does NOT Need:**
- Say "comply with specs" (automatic)
- Reference specific spec files (Claude finds them)
- Remind about security (Claude knows)

**Example Session:**
```
User: "I need to query user data from PostgreSQL"

Claude: "I'll implement this following our security specifications:
         - specs/architecture/database_layer.spec (connection pooling)
         - specs/security/sql_injection_prevention.spec (parameterized queries)
         - specs/security/secrets_management.spec (no hardcoded creds)
         
         My approach:
         1. Load DB credentials from environment
         2. Use connection pool
         3. Create query function with parameterized statement
         4. Add security tests
         
         Shall I proceed?"

User: "Yes"

Claude: [implements securely]
```

---

### VS Code / JetBrains Extensions - DEPENDS ON CONFIGURATION ⚠️

**What Happens:**
- Some extensions read `.claude/` directory (if configured)
- Some extensions ignore project files
- Behavior varies by extension version

**Recommendation:**
- Test if your extension auto-loads `.claude/`
- If not, use manual prompting (see below)

---

### GitHub Copilot / ChatGPT / Generic AI - MANUAL PROMPTING REQUIRED 🔴

**What Happens:**
```
User: "Create database connection"
  ↓
AI uses training data (may be insecure)
  ↓
AI generates: password = "hardcoded123"  ❌
```

**What User MUST Do:**
```
User: "Create database connection.
       MANDATORY: Read specs/architecture/database_layer.spec
       Use environment variables, parameterized queries."
  ↓
AI reads spec
  ↓
AI generates: password = os.environ.get('DB_PASSWORD')  ✅
```

**Template Prompt (copy-paste):**
```
I need to implement [TASK].

MANDATORY READING:
- .claude/project-instructions.md
- specs/[relevant-spec].spec

REQUIREMENTS:
- [Key requirement 1]
- [Key requirement 2]

Follow the specifications exactly.
```

## 🧪 Layer 2: Testing (ALWAYS REQUIRED)

**Enforcement:** Security tests catch violations, regardless of how code was generated.

**What Happens:**
```
Code generated (by AI or human)
  ↓
Developer runs: pytest tests/test_security.py
  ↓
Tests check:
  - No hardcoded secrets? ✅
  - All queries parameterized? ✅
  - Security headers set? ✅
  ↓
If FAIL → Developer must fix → Re-run tests
  ↓
If PASS → Proceed to commit
```

**Tests DON'T CARE how code was generated:**
- AI-generated code
- Human-written code
- Copy-pasted code

**Tests ONLY CARE:**
- Does it follow security specs? ✅/❌

---

## 🚫 Layer 3: CI/CD Gates (ALWAYS REQUIRED)

**Enforcement:** Automated scans in pipeline, blocks deployment on failure.

**What Happens:**
```
Developer pushes code
  ↓
GitLab CI/CD triggers
  ↓
Stage 1: Security Scan (BLOCKING)
  - detect-secrets → finds hardcoded password → FAIL → BLOCK
  - pip-audit → finds CVE in dependency → FAIL → BLOCK
  - bandit → finds SQL injection → FAIL → BLOCK
  ↓
Stage 2: Tests (BLOCKING)
  - pytest tests/test_security.py → FAIL → BLOCK
  ↓
Stage 3: Container Scan (BLOCKING)
  - trivy → finds HIGH CVE → FAIL → BLOCK
  ↓
If ANY stage FAILS → Deployment BLOCKED
Developer must fix → Push again → Re-run pipeline
```

**Pipeline DON'T CARE how code was generated:**
- Written by junior dev with AI
- Written by senior dev manually
- Generated by template

**Pipeline ONLY CARE:**
- Does it pass security scans? ✅/❌

| AI Tool | Auto-Loads Specs? | User Action Required | Compliance Level |

| **Claude Code** | ✅ Yes (`.claude/`) | Describe task | Semi-Automatic |

*AI guidance not required because Tests + CI/CD catch everything

## 🎯 Practical Recommendations

### For Claude Code Users (Easy Mode)
1. Open project → `.claude/` auto-loads
2. Describe tasks normally
3. Claude reads specs automatically
4. Run tests before committing
5. CI/CD validates before deployment

**Prompting effort:** Low ✅

---

### For Other AI Tool Users (Manual Mode)
1. Open `docs/PROMPTING_GUIDE.md`
2. Copy template prompt for your task
3. Paste + customize for specific task
4. AI reads specs (because you told it to)
5. Run tests before committing
6. CI/CD validates before deployment

**Prompting effort:** Medium ⚠️

---

### For No-AI Users (Traditional Development)
1. Read `docs/ENTERPRISE_STANDARDS.md`
2. Read applicable specs in `specs/`
3. Implement following patterns
4. Run tests before committing
5. CI/CD validates before deployment

**Manual effort:** High 🔴

## 💡 Key Insights

### Insight 1: AI Guidance is a Convenience Layer
- **Claude Code:** Makes it easier (auto-reads specs)
- **Other AI:** Still need to reference specs manually
- **But:** Security tests + CI/CD catch everything anyway

### Insight 2: Tests + CI/CD are the Real Enforcement
- Code can be generated any way (AI, manual, copy-paste)
- Tests validate compliance
- CI/CD blocks non-compliant code
- **This is the true "automatic" enforcement**

### Insight 3: Defense in Depth
```
AI Guidance (Preventive - varies)
    ↓
Security Tests (Detective - always)
    ↓
CI/CD Gates (Blocking - always)
```

Even if AI guidance fails, tests + CI/CD prevent bad code from reaching production.

Result: Secure code deployed
```

### Scenario 4: Senior Dev (No AI, Makes Mistake)
```

## ✅ Bottom Line

**Question:** Does the user need to specify "comply with specs"?

**Answer:**
- **With Claude Code:** No (semi-automatic via `.claude/`)
- **With other AI tools:** Yes (must reference specs in prompts)
- **But always:** Tests + CI/CD enforce compliance regardless

**Best Practice:**
1. Use Claude Code if possible (easiest)
2. If using other AI, follow `docs/PROMPTING_GUIDE.md`
3. Always run security tests before committing
4. Trust CI/CD to catch anything that slipped through

**Remember:** The template provides multiple safety nets. Even if AI guidance fails, automated testing and CI/CD ensure only compliant code reaches production.

## 🏢 Special Case: OpenShift Dev Spaces + Vertex AI Claude

### Environment
- **IDE:** Red Hat OpenShift Dev Spaces (cloud-based, Kubernetes-hosted)
- **AI:** Claude via Google Vertex AI (API-based integration)
- **Compliance Level:** 🔴 **Manual Prompting Required**

### Why Manual?
Vertex AI Claude is API-based and does **NOT** automatically read `.claude/` directory like Claude Code CLI does.

### Solution: Context Loading Script

**Location:** `.devspaces/load-context.sh`

**Usage:**
```bash
# In Dev Spaces terminal
./.devspaces/load-context.sh

# Copy entire output
# Paste into first Vertex AI Claude prompt
```

### Workflow

**Step 1: Start Session**
```bash
# Run in Dev Spaces terminal
./.devspaces/load-context.sh > /tmp/context.txt
cat /tmp/context.txt
```

**Step 2: Copy to Vertex AI Claude**
```
[Paste context from load-context.sh]

Now I need to implement [TASK].

MANDATORY: Read specs/[relevant-spec].spec first.
Requirements: [KEY_REQUIREMENTS]
```

**Step 3: Validate Locally**
```bash
# Run security tests
pytest tests/test_security.py -v

# Scan for secrets
detect-secrets scan --all-files

# Check dependencies
pip-audit -r requirements.txt
```

### Dev Spaces Commands

Configured in `.devfile.yaml`:

```bash
# Load AI context
oc exec <pod> -- .devspaces/load-context.sh

# Run security scans
oc exec <pod> -- pytest tests/test_security.py

# Build container (with Podman)
podman build -t app:latest .

# Scan container
trivy image app:latest
```

### Key Differences from Claude Code

5. **Same end result** - insecure code blocked

**Remember:** Context loading is manual, but enforcement is automatic (via tests + CI/CD).
